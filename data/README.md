# Data

**All data in this folder is synthetic.** It contains no real FIR, victim, accused or police data and must
never be mixed with real records. Real data, if ever used, goes in `data/real/` (git-ignored) under restricted,
access-logged storage.

| File | Rows | What it is |
|---|---|---|
| `synthetic/fir_reports.json` | 4 | FIR, surveillance and intelligence notes (free text) |
| `synthetic/social_media_posts.json` | 3 | Tips from X, Facebook and a WhatsApp tipline (free text) |
| `synthetic/cdr_records.csv` | 18 | Call detail records between suspects |
| `synthetic/criminal_history.csv` | 8 | Known people: phone, vehicle, aliases, prior cases, address |
| `synthetic/financial_transactions.csv` | 8 | Bank / UPI transfers between suspects and a trading firm |
| `fir_cases.csv` | 2,412 | FIR case register generated by `generate_fir_cases.py` (seed 42) |

## Schemas

### `synthetic/fir_reports.json`
| Column | Type | Description |
|---|---|---|
| `document_id` | string | `FIR-45-2023`, `SURV-2026-114`, `INTEL-2026-07`... |
| `document_date` | date (YYYY-MM-DD) | date of the report |
| `text` | string | narrative naming people, phones, vehicles, places, firms |

### `synthetic/social_media_posts.json`
| Column | Type | Description |
|---|---|---|
| `author` | string | handle of the poster (`unknown_user92`, `citizen_tipline`...) |
| `platform` | string | X, Facebook, WhatsApp Tipline |
| `timestamp` | datetime | when it was posted |
| `text` | string | tip text (may use aliases such as "Vicky bhai") |

### `synthetic/cdr_records.csv`
| Column | Type | Description |
|---|---|---|
| `caller`, `callee` | string (10 digits) | phone numbers (kept as text, never as numbers) |
| `caller_name`, `callee_name` | string | subscriber names; may be written in different orders (`Rathore Vikram`) |
| `timestamp` | datetime | call start |
| `duration_seconds` | int | call length |
| `tower_location` | string | cell tower area |

### `synthetic/criminal_history.csv`
| Column | Type | Description |
|---|---|---|
| `name` | string | canonical name |
| `phone` | string | phone number, links to CDR |
| `vehicle` | string | registration number, links to FIR / social text |
| `aliases` | string | comma-separated aliases (`Vicky`, `Ramu`, `Zubi`) |
| `prior_cases` | string | `FIR 45/2023 - Extortion; ...` |
| `address` | string | area and city |

### `synthetic/financial_transactions.csv`
| Column | Type | Description |
|---|---|---|
| `from_account`, `to_account` | string | `ACC1001`... |
| `from_name`, `to_name` | string | account holders (people or `Chatterjee Traders`) |
| `amount` | int (Rs) | amount transferred |
| `timestamp` | datetime | transfer time |
| `mode` | string | NEFT, RTGS, UPI |

### `fir_cases.csv` (generated case register)
| Column | Type | Description |
|---|---|---|
| `fir_no` | string | `STATION/serial/year`, e.g. `RJW/0042/2025` |
| `police_station`, `district` | string | station (deliberately misspelt in some rows) and district |
| `date_occurred`, `date_registered` | date | `date_registered` mixes `YYYY-MM-DD` and `DD/MM/YYYY` on purpose |
| `hour_of_occurrence` | int 0-23 | some missing |
| `crime_type` | string | 12 types (Theft ... Sexual Offence) |
| `ipc_sections` | string | IPC / special-Act sections; mapped to BNS during cleaning |
| `offence_gravity` | Low / Medium / High | ordinal gravity of the offence |
| `modus_operandi` | string | MO text in English, Hindi (Devanagari) or Hinglish |
| `latitude`, `longitude` | float | synthetic incident location |
| `accused_names` | string | `; `-separated, or `Unknown` |
| `num_accused`, `num_witnesses` | int | some missing / impossible values on purpose |
| `complainant_name`, `complainant_phone`, `complainant_address`, `victim_name` | string | **fictitious** personal data, masked during anonymisation |
| `property_value_inr`, `property_value_lakh` | float | value involved; the lakh column is a redundant copy (for the correlation filter) |
| `io_id`, `io_caseload` | string, int | investigating officer and their open cases |
| `registration_delay_days` | int | days between offence and FIR |
| `has_cctv`, `has_cdr_evidence`, `has_financial_trail`, `forensic_required` | Yes / No | evidence flags |
| `case_status` | string | Under Investigation, Chargesheet Filed, Closed - Final Report |
| `chargesheet_date` | date | empty while pending |
| `court_status` | string | Pending Trial, Convicted, Acquitted (empty if no chargesheet) |

The supervised target `chargesheet_delayed` is derived during preprocessing: 1 if the chargesheet was filed after
90 days or is still pending after 90 days (as of 2026-09-30), 0 if filed within 90 days, and left empty (excluded
from training) for younger pending cases and closures.

## How the files link together

```
criminal_history.name/aliases ──┬── cdr_records.caller_name / callee_name   (name variants, aliases)
criminal_history.phone ─────────┼── cdr_records.caller / callee              (phone number)
criminal_history.vehicle ───────┼── vehicle numbers in fir_reports / social_media text
criminal_history.name ──────────┼── financial_transactions.from_name / to_name
criminal_history.prior_cases ───┼── fir_reports.document_id  (FIR 45/2023 = FIR-45-2023)
criminal_history.address, cdr.tower_location, place names in text ── fir_cases.police_station
criminal_history.name (+ Anita Deshmukh) ── fir_cases.accused_names  (repeat offenders, co-accused network)
```

There is no single numeric key: people are resolved by name normalisation, alias lookup, fuzzy matching, phone
and vehicle numbers (`src/preprocessing.py`, `PersonRegistry`).

## Why `fir_cases.csv` is generated

The five provided files contain no case-register fields (crime type, station, chargesheet and court outcome) and
far fewer than the 1,000 rows the CSL236 end-term guidelines require. The guidelines allow "a synthetic one you
generate with a documented script", so `generate_fir_cases.py` builds a register that reuses the people, places
and modus operandi of the five files. It is seeded, so the file is identical on every run; CI regenerates it and
checks that it matches byte for byte.

```bash
python data/generate_fir_cases.py            # writes data/fir_cases.csv (2,412 rows x 31 columns)
python data/generate_fir_cases.py --n 5000   # larger register
```

Data-quality problems are injected deliberately (12 duplicate rows, misspelt station names, mixed date formats,
missing values, `num_accused = 99`, negative registration delays) so the cleaning stage has real work to do.

## Optional external data for trend validation

The project runs entirely on the files above. For extra trend validation you can download the Kaggle
"Indian Crimes Dataset" or NCRB district-wise IPC tables into `data/external/` (git-ignored if you add it to
`.gitignore`) and compare city-level trends; this is not required by any notebook cell.
